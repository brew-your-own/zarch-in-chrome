# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Goal

A browser clone of **Zarch** (David Braben, Acorn Archimedes, 1987), later ported to Atari ST / Amiga as **Virus**. Stack: Vite + TypeScript + Three.js, tests with Vitest.

Current scope: a title screen in attract mode, craft, terrain with trees, launch pad, fuel, auto-refuel (R, once per wave), landing/crashing with explosions, the cannon (right mouse button), seeder enemies spreading the virus in waves, mutants (seeders left alive too long, which dive at the craft), bombers that lay the virus in lines from wave 3, fighters that hunt the craft from wave 2, a difficulty curve, smart bombs (Space) and homing missiles (middle button or E), lives (3 by default), a procedural soundtrack, score, a pause/settings panel and three preset maps. The game ends when the virus covers `enemies.overrunAt` of the land (60% by default), or when the last life is lost. Buildings and the original's pests are not built yet. A bullet destroys the tree it hits. Destroyed trees stay gone until the map is rebuilt, which happens on a map change or a page reload.

## Commands

- `npm run dev`: dev server (http://localhost:5173).
- `npm run build`: type-check with `tsc --noEmit`, then `vite build`.
- `npm run typecheck`: type-check only. There is no separate linter. `tsconfig` is strict, with `noUncheckedIndexedAccess`.
- `npm test`: run all tests once. `npm run test:watch` runs them in watch mode.
- Single test: `npx vitest run src/sim/craft.test.ts -t "lands softly"`
- Deploy: every push to `main` runs `.github/workflows/deploy.yml`, which tests, builds and publishes `dist/` to GitHub Pages at https://brew-your-own.github.io/zarch-in-chrome/. `vite.config.ts` sets `base: './'` so the build works under that sub-path. The remote is owned by the `brew-your-own` GitHub account, not the work account.

## Architecture

The code has a hard split between simulation and presentation:

- `src/sim/`: pure, deterministic game logic with no DOM or Three.js imports. Everything testable lives here, and new gameplay rules belong here with tests.
  - `terrain.ts`: `Terrain` is a wrapping (toroidal) heightmap, one world unit per tile. World coordinates are unbounded and lookups wrap with `mod`. Each tile is split into two triangles along the (0,0)-(1,1) diagonal. `heightAt`, `normalAt` and `render/terrainView.ts` must all agree on that split. `generateTerrain(seed, options)` builds seeded multi-octave value noise (`amplitude`, `seaBias` and `roughness` shape it), clamps it to `SEA_LEVEL`, flattens a 3×3 launch pad in the middle of the map, then plants trees. Tests build small hand-written worlds with `Terrain.fromRows(...)` instead of using generated ones.
  - `trees.ts`: at most one tree per tile, stored in `Terrain.trees` (`treeAt`/`setTree`) and placed at the tile centre. `TREE_SHAPES` gives each kind's collision cylinder. `treeScale`/`tileHash` give each tile a stable size and variation, and the renderer must use the same ones so the trees you see match the ones you hit. `plantTrees` uses its own random stream, so tree density never changes a map's heights. It keeps the pad and the ring of tiles around it clear, so the spawn point is always safe. `hitsTree` checks the 3×3 neighbouring tiles, because a round canopy can reach across a tile border.
  - `virus.ts` and `Terrain.infection`: one flag per tile. `Terrain.infect` only takes on clean land, never sea or the pad, and keeps `infectedCount`. `stepVirus` gives each infected tile a `rate`-per-second chance to infect a random neighbour, using a random stream passed in so tests are deterministic.
  - `enemies.ts`: seeders and spores. `stepEnemies(enemies, craft, bullets, terrain, dt, settings, physics)` does several things:
    - runs waves: the first has `firstWave` seeders and each later one adds one. Waves spawn at least 16 tiles away. Setting `firstWave` to 0 turns enemies off.
    - flies seeders between random waypoints at `SEEDER_CRUISE` above the ground under and just ahead of them.
    - drops spores over clean land; a spore infects the tile it lands on.
    - spreads the virus.
    - resolves bullet and craft collisions: it removes the bullets that hit, scores the kills, and calls `crashCraft` when a seeder rams the craft.
    - flies fighters and their shots (see `fighters.ts`). Wave n brings `round(fighters × (n − 1))` fighters, and from wave `bombersFromWave` on, `bombers` bombers (see `bombers.ts`). The next wave waits until every enemy is gone.
    - turns each seeder that has lived `mutateAfter` seconds (0 = never) into a mutant with the same id (see `mutants.ts`), with a `seederMutated` event. Mutants and bombers drop spores too.
    - applies the difficulty curve: it works from `waveSettings(settings, wave)`, a copy of the settings for the current wave. Each wave after the first raises a factor by `difficultyRamp`, capped at `difficultyCap`. That factor divides the spore, fighter-fire and mutation intervals, half of it speeds up every enemy, and fighter accuracy rises with it up to 0.85. Virus spread and the game rules are left alone. Wave 1, or a ramp of 0, uses the settings as they are.

    It returns `EnemyEvent`s for the renderer. `targets(enemies)` lists every enemy of every kind as `{ id, pos, radius }`, and `killEnemy(enemies, id, byBullet)` removes one whatever its kind, scores it (only when `byBullet`, which also covers missiles and bombs) and returns its event; bullets, ramming, bombs and missiles all go through these two, so a new enemy kind only needs adding there. `enemyCount` counts them all. A bullet takes one of a bomber's `BOMBER_HITS` and gives `bomberHit` until the last. `nearestEnemyDistance` gives the wrapped horizontal distance to the closest enemy, for the proximity alarm. `EnemySettings` also holds the game rules shown in the panel's Game section: `lives` and `overrunAt`. `isOverrun(terrain, settings)` is the game-over rule. Seeder and spore positions are kept **wrapped** into `[0, size)`, while the craft and bullets are not, so every comparison goes through `Terrain.delta`, the shortest wrapped distance. Use `Terrain.wrap` and `Terrain.delta` for any new code that deals with world positions.
  - `autopilot.ts`: auto-refuel. `AutopilotSettings.enabled` switches the feature on or off from the panel. `toggleAutopilot` engages it once per wave (`usedInWave`; with enemies off, wave stays 0, so once per game), or cancels it, which still spends the wave's use. It won't engage while the craft is wrecked or already sitting on the pad. `stepAutopilot` returns the `CraftInput` to use in place of the player's, or null, and lets go once the craft has landed on the pad, crashed, or the feature is switched off. `steer` (shared with the demo pilot) turns a wanted velocity into a `CraftInput`. The controller climbs to `CLEARANCE` above the highest ground or treetop along the next `LOOKAHEAD` units of the route, cruises towards the pad and eases off as it nears, then descends onto the pad. Thrust is on/off, so it holds a target vertical speed by switching thrust every step. The lean gives the horizontal acceleration, capped at `MAX_LEAN` and at the lean where full thrust can still hold altitude. The tests fly it from many points on every preset map, so retuning the controller or physics defaults must keep those landings safe.
  - `fighters.ts`: fighters close to a per-fighter stand-off distance from the craft and circle it, flying just above it but never below `FIGHTER_FLOOR` over the ground here and ahead. Within `FIRE_RANGE` they fire slow `EnemyShot`s (`SHOT_SPEED`, about a second's flight) every `fighterFireInterval`-ish seconds. `fighterAccuracy` (0-1) sets both the random spread and how much of the craft's motion they lead. The lead grows with the square of accuracy, so at the default a craft that keeps moving is rarely hit, while one hovering still is hit often. A test pins that dodgeability, so retuning the aim must keep it. They hold fire while the craft is wrecked or landed on the pad, so the pad is a safe haven. `moveShot` moves a shot in two half steps and reports whether it hit the craft or was spent on the ground, a tree or old age. Like seeders, fighters and shots are kept wrapped. A bullet kills a fighter (`FIGHTER_POINTS`), and ramming wrecks both. Events: `fighterDestroyed`, `fighterFired` (for the sound) and `craftShot`.
  - `mutants.ts`: a mutant stalks the craft from `STALK_ABOVE` over it, circling and swaying in and out, then dives in a straight line at `DIVE_BOOST` × `mutantSpeed` towards where the craft is heading (leading `DIVE_LEAD` of its motion), pulls out above `MUTANT_FLOOR`, climbs away (`recover`) and stalks again. It only dives from within `DIVE_RANGE`, and never at a wrecked craft or one on the pad. A test pins the dodgeability: a hovering craft is always rammed, one that keeps moving at 4 u/s rarely is, so retuning the dive must keep that.
  - `bombers.ts`: a bomber flies straight along one of the eight compass directions at `BOMBER_CRUISE` over the ground, alternating `RUN_LENGTH`-tile bombing runs (a bomb every tile, as a spore, so the virus lands in a line) with longer gaps, after which it may turn by 45°. It takes `BOMBER_HITS` bullets; a missile or bomb kills it outright.
  - `weapons.ts`: the special weapons, held in an `Arsenal` (`bombs`, `missiles`, `inFlight`) and tuned by `WeaponSettings` (`settings.weapons`). `main.ts` calls `restock` on each `waveStarted` event. It resets bombs to `bombsPerWave` from wave `bombsFromWave` on, so unused bombs don't carry over, and adds `missilesPerWave` missiles, which build up to `MAX_MISSILES`. `detonateBomb` destroys and scores every enemy within `bombRadius` of the craft (wrapped distance), and removes the spores and enemy shots there too. `fireMissile` launches from the nose, locked onto the nearest enemy of any kind within `MISSILE_RANGE`. With nothing in range the missile stays in stock. `stepMissiles` turns each missile towards its target at up to `missileTurnRate`, picks a new target if its own is gone, and accelerates it to `missileSpeed`. A hit gives the same `…Destroyed` events as a bullet, and a missile that hits the ground or a tree, or gets too old, gives `missileSpent`. Missiles are unwrapped, like bullets.
  - `titleMap.ts`: the title screen's world. `buildTitleMap()` makes a small (32-tile) gentle map and writes ZARCH north of the pad, from a 3×5 pixel font with each pixel one tile wide and two deep (the slanted camera squashes the letters front to back). The word stands on a flat plinth, with the letter tiles embossed a little, and trees are cleared around it. It returns `letters`, a per-tile mask (1 for lettering, 2 for the rest of the plinth), which only the palette reads, and `centre`. `lettersInfected` gives the share of letter tiles the virus has taken.
  - `demoPilot.ts`: the title screen's computer pilot. `stepDemoPilot` returns a `DemoCommand`: the craft input plus the fire, bomb and missile presses and its `mode`. It hunts seeders within `LEASH` of `home` (the lettering), patrols near home when there are none in reach, and flies to the pad (with `autopilotInput`) to refuel when low on fuel or between waves, waiting there for the next wave. A hunt is a series of gun runs: the nose only points where the craft leans, and dips with it, so the pilot leans gently at the target from a little above it, and backs off when too close. It fires only when `wouldHit` says a bullet fired now would pass within reach of the seeder, both flying straight. `DEMO_ENEMIES` are the title's enemy settings: fewer, slower seeders that never mutate, no fighters or bombers, and a quicker virus. The tests run the whole attract mode and check that the pilot kills seeders, seldom crashes, uses every control, and still loses to the virus in the end, since that is what restarts the title loop.
  - `noise.ts`: `valueNoise`, a single wrapping octave, shared by the heightmap and the forest layer. Changing the order in which it draws random numbers changes every map.
  - `maps.ts`: the preset maps (`MAPS`), each a seed plus terrain options. `maps.test.ts` checks that each preset keeps its character (sea fraction, peak height), so retuning a preset may mean updating those bounds.
  - `craft.ts`: `stepCraft(state, input, terrain, dt, physics)` mutates `CraftState`. The input aim is a point in the unit disk (the virtual mouse position relative to the screen centre). Its direction sets which way the craft leans and its distance sets how far, up to `physics.maxTilt`. Thrust always pushes along the craft's tilted up axis, against constant gravity. A landed craft is held upright whatever the mouse does, so it always lifts off vertically, and it levels out on a safe touchdown. `main.ts` also recentres the aim on every step while landed, so the craft starts each liftoff with the mouse at centre. The craft crashes on any overlap with a tree (`CRAFT_RADIUS` against the tree's cylinder). On the ground, it only crashes on the *transition* from flying to touching down: too fast, too tilted, too steep, or over sea. `state.thrusting` records whether the thruster actually fired that step. When the craft crashes, `vel` is left at the impact velocity rather than zeroed, because the explosion uses it. A crashed craft doesn't move. Tuning is a `Physics` object passed in (defaulting to `DEFAULT_PHYSICS`), so it can change at runtime; `tiltAngle`, `thrustDirection`, `noseDirection` and `spawnCraft` take it too. `noseDirection` (where the cannon points) dips as the craft leans. `render/orientation.test.ts` checks that it and `thrustDirection` match the renderer's Euler rotation.
  - `cannon.ts`: `stepCannon(cannon, craft, fire, terrain, dt, physics)` fires at `physics.fireRate` from the nose, with bullets inheriting the craft's velocity. It moves bullets in sub-steps (`CHECKS_PER_UNIT`) so they can't tunnel through trunks, and returns each step's `Impact`s (`ground`/`sea`/`tree`) for the renderer. A tree impact has already removed the tree from the terrain (`setTree(…, TREE_NONE)`) and carries its tile and kind in `impact.tree`. `trees.treeHit` reports which tree a point touches, and `hitsTree` is a boolean wrapper around it.
- `src/render/`: Three.js views that read sim state each frame and never change it.
  - `lighting.ts`: `SUN`, the single light direction. The CPU-shaded terrain, the minimap, the scene's `DirectionalLight` and the tree shadows all use it.
  - `palette.ts`: all world colours. A `Palette` is built per terrain (optionally with the title map's `letters` mask, painted as pale lettering on a dark slab, without the checkerboard) from the live `ColourSettings` (`autumn`, `grassTone`, `patches`, each 0–1), with `COLOUR_PRESETS` for the season buttons. `tile()` gives the ground colour, including the checkerboard and rust/orange/brown patches from a noise layer seeded by the terrain. `foliage()` gives tree colours: pines are always evergreen, and a hash-chosen share of round trees turns autumnal. Infected tiles and their trees take the `VIRUS` crimson, which is deliberately distinct from the autumn reds. The sim never reads colours.
  - `skyView.ts`: the night sky, made of a gradient dome and a twinkling star field centred on the camera. Because the camera always looks down, the visible strip of sky lies *below* true horizontal, beyond the far edge of the terrain patch, so the glow's "horizon" sits at a negative elevation (`HORIZON`). The star band turns with the craft's x, one full turn per map width, which gives a hint of parallax and lines up across the wrap. `skyView.fog` is the scene fog, coloured like the glow so the patch edge melts into it. Three.js fogs by straight-line distance, so `update` widens its range with camera height, and by an extra `reach` for a camera standing further back.
  - `cameraRig.ts`: `CameraRig` places the camera every frame. It follows the craft from behind and above (`OFFSET`, fixed `PITCH`). It rolls with the craft's sideways tilt, stands further back by `frame(pull)` (eased, so leaving the title screen is a swoop down to the craft; `extraReach` lets the sky push the fog out to match), lengthens the offset as the craft climbs (`zoomFactor`, up to 1.5× by 12 units), and shakes after explosions. Shake uses trauma: `shake(strength, distance)` adds trauma that falls off with distance and decays over time, and the offset is trauma² times a smooth wobble. Shake only advances with unpaused time. `CameraSettings` (`lean`, `shake`, `zoom` multipliers) come from the panel's Camera section. `main.ts` calls `rig.shake` alongside each explosion sound and `rig.snap` from `resetMotion`.
  - `terrainView.ts`: rebuilds a fixed-size patch of tiles around the craft every frame, skewed so more rows lie north. Lighting is calculated per triangle on the CPU into vertex colours for the flat-shaded look, so the terrain doesn't use scene lights. Base colours come from the `Palette`. Open water moves: a vertex whose four surrounding tiles are all sea (precomputed per terrain in `openWater`) is raised by `waveHeight`, two crossing wave trains whose wavelengths divide the map size so they line up across the wrap. Shore vertices stay put, so land and sea never come apart. Sea triangles are lit with their slopes exaggerated (`WAVE_GLINT`) so the facets glint. The waves are cosmetic: the sim still treats the sea as flat at `SEA_LEVEL`.
  - `treeView.ts`: two `InstancedMesh`es per tree kind, wood and foliage, refilled each frame for the same visible patch as `terrainView` (it imports the patch constants from there). Foliage geometry is painted in grey levels and gets its hue from the per-instance colour, so leaves can change colour without tinting trunks. Tree shadows are flat side-on outlines cast along `SUN` and draped onto the terrain, drawn as one translucent mesh. The craft's shadow, by contrast, falls straight down, because it doubles as an altitude cue.
  - `craftView.ts`: the low-poly craft mesh, plus a shadow made by dropping each craft vertex straight down onto `terrain.heightAt`.
  - `exhaustView.ts`: the thruster plume, a cosmetic `ParticlePool` driven by frame time rather than the fixed sim step. It emits while `state.thrusting` is set and freezes while paused. Its look comes from a `PlumeSettings` object (`DEFAULT_PLUME`).
  - `particles.ts`: `ParticlePool`, a ring buffer of square particles with gravity, terrain bounce and colour ramps. It's shared by the exhaust plume and the effects.
  - `effectsView.ts`: explosions and bullet impacts. `shatter()` breaks any coloured, non-indexed geometry into spinning shards that bounce on the terrain and shrink away; a `ShatterStyle` sets how much incoming momentum they keep and how hard they are kicked. All wrecks share one 256-shard pool, oldest dropped first. `explode()` shatters the craft, with each triangle split into four, carrying its impact velocity, plus fire and smoke. `main.ts` calls it on the step where `status` becomes `crashed`. `destroyTree()` shatters a shot tree, plus fire and leaves. `splash(pos, size)` throws up spray from the sea surface. Bullets hitting the sea splash, an explosion at the water's surface adds a big splash, and shards that land on sea sink with a small one. `update()` returns where shards sank this frame, so `main.ts` can play a (rate-limited) splash sound. `bomb(pos, radius)` expands the additive `shockwave` ring (which `main.ts` adds to the scene) out to the bomb radius, with a burst of fire. `missileTrail(pos)` leaves smoke behind a missile, and `pop(pos)` is a spent missile's small blast. Because the sim has already removed the tree, its shape comes from `TreeView.shape(i, j, kind)`, which bakes in the palette colours.
  - `seederView.ts`: seeders (an `InstancedMesh` of spinning tops), mutants (spiky green and crimson balls, spinning and tumbling), their straight-down shadows and the falling spores. Each is drawn at its wrapped position nearest the camera focus, and only inside the visible terrain patch. `shape()` and `mutantShape()` give the geometry and pose to shatter with `EffectsView.explode`. `EffectsView.mutation(pos)` is the spark burst when a seeder mutates.
  - `bomberView.ts`: bombers as an `InstancedMesh` of olive flying wings, rolling into turns, with straight-down shadows and a `shape()` for shattering.
  - `missileView.ts`: in-flight missiles as an `InstancedMesh` of white cones pointing along their velocity.
  - `bulletView.ts`: tracer lines plus head points for the live bullets. A second instance in `FIGHTER_TRACER` colours draws the fighters' shots, passing `wrap` so wrapped positions are drawn at their copy nearest the camera.
  - `fighterView.ts`: fighters as an `InstancedMesh` of red darts, pitched with their climb and banked into turns (the turn rate is tracked per fighter id), with straight-down shadows. `shape()` feeds `EffectsView.explode` like seeders do.
  - `minimap.ts`: `terrainImage()` renders a whole terrain as a one-pixel-per-tile canvas, north up. `drawMinimap()` scales it into a canvas with markers. Colours come from the `Palette`, with forests in their foliage colour. The pause panel uses it for the map thumbnails and the current-map view with the craft marker.
- `src/audio/sound.ts`: `SoundEngine`, procedural Web Audio with no sound files. It plays a looping brown-noise thruster roar, a square-wave cannon blip with a noise click, and a two-note chime when the autopilot engages, a proximity alarm alternating a low tone and its octave every 0.5 s, splashes, a smart-bomb boom with a falling sub-bass sweep (`bomb`), a missile whoosh (`missile`), a warbling squeal when a seeder mutates (`mutation`), a metallic clank when a bullet hits a bomber that survives (`clank`), and noise-burst explosions sized by `EXPLOSION_SIZE` (craft > bomber > fighter > mutant > seeder > tree) and quietened with distance (`attenuation`). The `AudioContext` is only created in `resume()`, which must run inside a click handler; Fly and Play again both call it. Until then every method is a no-op, so tests and the sim never need audio. `main.ts` plays explosions from the sim events. Its `playSounds()` drives the thruster from `craft.thrusting` and plays one blip per increase in `cannon.shots`. Fighter shots (`enemyShot`) and fighter explosions are played from the sim events. Volume is `settings.sound.volume`. The proximity alarm starts at `settings.sound.alertDistance` tiles from the nearest seeder (0 turns it off). `proximityLevel` maps that distance to a 0-1 level, rising from quiet at the alert distance to full at `FULL_ALERT_DISTANCE`. `main.ts` computes the level once per frame from `nearestSeederDistance`, keeps it at 0 while paused, crashed or game over, and feeds it to the sound engine, the HUD ("ENEMY CLOSE") and the scanner, which draws the alert distance as a ring around the craft that turns red while the alarm sounds.
- `src/audio/music.ts`: the soundtrack. `musicStep(step, intensity)` is the pure score: a four-bar A minor loop, one call per sixteenth note, where layers join at the `LAYERS` thresholds (pad, bass, hats, arpeggio, kick, snare). Above `TENSE_AT` the chords turn darker, and `tempo` rises with intensity. `MusicPlayer` schedules the score ahead on the AudioContext clock from its own timer, so the beat doesn't depend on the frame rate, and glides the intensity over `INTENSITY_GLIDE` seconds. `SoundEngine.music(intensity, quiet, dt)` drives it at `settings.sound.music` volume, quieter while paused or after game over. `main.ts` `musicIntensity()` combines a base level with whether enemies are about, the virus share, the proximity alarm level and being on the last life.
- `src/input.ts`: pointer-locked mouse. Movement is added up into the aim disk. Left button is thrust, right button is fire, and the middle button sets `missile` (as does E, from a `keydown` listener in `main.ts`).
- `src/settings.ts`: the `Settings` object (`physics`, `plume`, `colours`, `enemies`, `weapons`, `autopilot`, `camera`, `sound`, `mapId`), saved to `localStorage` and loaded over the defaults. Loading skips unknown keys and any value whose type (number or boolean) differs from the default's, so adding a new setting only needs a default. The `physics`, `plume`, `colours`, `enemies`, `weapons`, `autopilot`, `camera` and `sound` objects are **mutated in place** by the panel. The sim and views hold references to them, so never replace those objects.
- `src/ui/hud.ts`: the HUD, built as DOM in `#hud`. It has the fuel bar, which turns red and warns below `LOW_FUEL`, flight, score, wave, lives and virus readouts, an ARMS row (bombs and missiles in stock), a pad compass, the auto-refuel state and a status line, plus a "WAVE n" banner. `padBearing()` gives the screen bearing to the pad. Because the camera always faces north, a world bearing is a screen bearing.
- `src/ui/scanner.ts`: the live map in `#scanner`, stacked under the HUD in `#hud-column` at the same width. It's centred on the craft and tiles the cached `terrainImage` across the wrap. The image is refreshed every 0.5 s, or immediately when the terrain or palette changes. The craft, pad and enemies (seeders, blinking green mutants, fighters and bomber chevrons) are redrawn every frame.
- `src/ui/titleScreen.ts`: the title screen's DOM in `#title`, over the attract mode: a tag line, the goal, the control chips (lit for a moment each time the demo pilot uses that control, from the `ControlSignals` `main.ts` gathers each frame), Fly and Settings, the best score, the map arrows, the "virus has taken the land" banner, and a link to the GitHub project (`github.ts`, also in the settings panel's header).
- `src/ui/gameOver.ts`: the end screen in `#gameover`, with Play again and Title screen, the reason (`virus` or `lives`), plus the best score kept in `localStorage` (`zarch.best.v1`, read and written through try/catch).
- `src/ui/settingsPanel.ts`: the settings screen in `#overlay`, opened in one of two `PanelContext`s. From the title it has Back (or Esc) and its minimap shows the map picked for the next game, and picking a map just selects it. Paused in a game it has Resume (which requests pointer lock) and Quit to title, its minimap shows the game with the craft and enemies, and picking a map starts a new game there. It also has the map picker, sliders and colour presets. It redraws the minimap and thumbnails on each change, so colour edits show up there immediately. Boolean settings use `toggle()` checkboxes. The Game section holds lives, the difficulty ramp and cap, and the overrun share; the Weapons section holds `settings.weapons`. Sliders are declared as `SliderSpec` lists; `scale` converts stored units to displayed ones, e.g. radians to degrees.
- `src/main.ts`: wiring and the game loop. It runs in one of two modes. In `'title'` (attract mode, where the page starts), `title` holds the title map, the demo pilot flies the craft with `demoEnemies`, the sim runs without pointer lock, effects and sounds are silent (`sfx()` is null), lives aren't counted, and the HUD and scanner are hidden. The camera stands back by `TITLE_PULL` and centres on a smoothed `focus` between the lettering and the craft, and the drawn patch sits south of the focus to cover the near ground. `recentreDemo` moves the craft, its bullets and missiles back by a whole map width after a chase across the wrap, so it stays drawn near the lettering. Once `DEMO_LOST_AT` of the lettering is infected the banner shows, and `DEMO_RESTART_DELAY` seconds later `newTitleWorld()` starts the title world again. Fly calls `startGame()`, which switches to `'game'` on `settings.mapId` and lets the camera swoop in. Quit to title and the game over screen's Title button call `enterTitle()`. Views hold the terrain they draw, so changing the map rebuilds them with `buildViews()`, respawns the craft and resets the cannon and enemies. `newGame(mapId)` builds a fresh world, used by map changes and Play again. `endGame()` freezes the sim, records the score and releases the pointer. While game over is set, the pointer-lock callback shows the end screen rather than the panel. On the title screen, it shows nothing. `MouseInput.requestLock` reports a refused lock as unlocked, so a pause screen always comes back. The arsenal is reset in `newGame`. In a game, each sim step asks `stepAutopilot` for input first, keeping the mouse aim in step with the autopilot so taking back control doesn't jolt the craft. When the autopilot lands and lets go, a thrust button still held is ignored until released, so the craft doesn't take straight off again. R toggles the autopilot through a `keydown` listener. Each sim step then runs `stepCraft`, then `stepCannon`, then `stepEnemies`, then a smart bomb if Space was pressed (`bombRequested`), a missile launch if `input.missile` is set, then `stepMissiles`, then the overrun check. All sim events go through `showEvent`, which plays the explosion, sound, shake and flash for each one and restocks the arsenal on `waveStarted`. The craft's explosion is triggered after all three, because a seeder or a fighter can wreck the craft too. That is also where a life is lost. With none left, the game ends `LAST_WRECK_PAUSE` seconds before the wreck would respawn. Lives reset to `enemies.lives` in `newGame`, so a changed setting applies from the next game. The simulation runs at a fixed 60 Hz with an accumulator, and rendering interpolates the craft position between the last two steps. In a game, the simulation pauses while the pointer is not locked.

In dev builds, `window.zarch` exposes `{ craft, cannon, autopilot, enemies, arsenal, input, settings, sound, demo, mode, lives, terrain, gameOver }`. The page opens on the title screen, whose attract mode runs without pointer lock. Browser automation can't take pointer lock, so clicking Fly leaves the game paused with the panel up. To drive the game, set `zarch.input.locked = true`, then set `aimX`/`aimY`/`thrust`/`fire`. Also hide `#overlay` before taking screenshots. Settings persist in the browser's `localStorage` under `zarch.settings.v1`, and the best score under `zarch.best.v1`, so clear both keys after testing. Changing `zarch.settings` directly, without the panel, isn't saved.

### Coordinate conventions

- Y is up. The camera has a fixed orientation: it always looks north (-z) from behind and above the craft, and only its position follows the craft.
- Screen up (aim +y) maps to world -z, and screen right maps to +x.
- The craft's heading is `atan2(tilt.x, -tilt.z)`. The nose is along local -z.
